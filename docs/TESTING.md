# 测试与验收

先运行 `./scripts/build.sh Debug`、`./scripts/build.sh Release`、`./scripts/test-core.sh`、`./scripts/test-web.sh`。测试在 Mac 临时目录创建文件，结束后清理；HTTP 测试先杀 18080 监听端口，服务结束后关闭。没有真机则不能标记整体验收通过。

## Phase 1：摄像头

在 iPhone 8 Plus / iOS 16.7.16 使用 Personal Team 安装，点击开始，允许摄像头与麦克风。录像一分钟，停止后播放，确认画面、正常声音、文件导出可播放。再拒绝权限，验证提示和重试；锁屏／电话／切后台验证明确停止且原文件不被主动删除。

## Phase 2：切片

Debug 开发者设置选 1 分钟，连续录制约 10 分钟，停止并导出。期望约 10 段，全部可播放、都有声音，metadata 时长、大小、编码与实际一致。记录每次切段间隙与音频中断，不能只数文件。测试后恢复“正常时长”，正式默认 10 分钟。

在 Mac 可使用 `afinfo 路径.mov` 查看音轨；用 QuickTime 从头、中间、结尾播放。用 Xcode Devices and Simulators → 设备 → App → Download Container（可用时）或 Finder 文件共享导出 JSON 与 MOV。不要用模拟器生成视频替代本项。

## Phase 3：循环存储

使用没有私人资料的测试素材，Debug 300 MB、30 秒切片。至少保留一段、让一段 pendingLock、继续录制直至占用触发清理；验证最老未锁文件删除，而当前／locked／pendingLock 不删除。保护素材过多时显示配额未满足提示。模拟低磁盘开关应停止并完成当前文件，不会制造真实磁盘占满。

## Phase 4：保留最近

分别测试 10／30／60 分钟，覆盖边界相交、多段、当前片段；操作后立刻重启读取 JSON 检查保护状态。等待当前段封装后 pendingLock 应转 locked。取消锁定后才允许循环删除。已保留素材人工删除需要确认。

## Phase 5：电脑控制

同 Wi-Fi 电脑打开手机地址。匿名 GET status 和所有修改接口应返回 401。错误配对五次冷却；正确配对后验证 status／start／stop／keep／clips／lock／unlock／timeline／daily-summary／settings。重配对后旧令牌 401。验证关闭开关、手机后台、critical 暂停，前台恢复后可重新连接。公开 Wi-Fi 隔离设备互访是网络问题，不能通过关闭认证绕过。

## Phase 6：转写

先 1 分钟、再 10 分钟讲中文，并在已知秒数说测试句。确认录制结束后才提取音频，一次一个片段；时间戳跨 55 秒边界仍落在原片段的正确位置。测本地不支持且在线关闭的提示；同意在线后测限流／断网／拒绝授权／取消。检查 temporary Speech 目录完成后移除。

## Phase 7：DeepSeek

用户自行配置 Key。测试连接，选择已完成转写片段重新分析，确认 JSON、摘要、主题、观点和时间轴范围；点击事件跳到原录像相应秒数。无 Key、错误 Key、无余额、错误模型、断网、超时及非法 JSON 只使 AI 失败，录像继续。日志不得出现 Key 或完整内容。

## Phase 8：每日总结

至少 3 段不同主题的已完成分析，点击生成今日总结。检查只基于片段摘要，包含实际素材引用，重启后可读。删除某原片段后总结仍为历史快照，但不可播放不存在的片段。

## Phase 9：长时间稳定性

保持前台、固定手机、接通电源；依次 2 小时 → 4 小时 → 8 小时。每次独立填写：

| 项目 | 记录值 |
| --- | --- |
| 设备／系统／构建版本 | |
| 开始／结束时间与实际时长 | |
| 初始／结束电量，是否充电 | |
| 起始／峰值 thermalState，暂停次数 | |
| 初始／结束剩余空间 | |
| 片段数量、失败数、间隙 | |
| 随机回放首／中／末片段的音视频 | |
| AI 关闭与开启的影响差异 | |
| 网络断开时录像是否继续 | |
| 中断、强杀、恢复结果 | |

先测纯录像，再测 Web，再启用 AI。记录实际结果，遇到发热先减少非关键任务，不能为了测试强制持续严重过热。所有实际硬件项目当前为 NEEDS PHYSICAL DEVICE TEST。

## 新版取景与镜头切换验收

以下全部为 **NEEDS PHYSICAL DEVICE TEST**，请在 iPhone 8 Plus／iOS 16.7.16 更新安装后执行：

1. 待机连点切换、切换时点开始、拒绝权限后重试：不得重入、偷偷录制或创建空素材；失败应有提示，原镜头可恢复或明确要求重建。
2. 前后各录一分钟，停止保存并播放；检查画面、声音、720p 或实际回退格式、fps、编码、竖屏方向。用有文字的纸验证前置预览镜像但文件不镜像；切换不应丢掉音轨。
3. 录制中点击切换应保存当前段并自动用另一镜头续录，计时不重置。原文件仍能播放，locked／pendingLock 保持；切换期间连点不得重复换镜头，停止必须立即取消续录意图，待保存完成后不再录制。分别在当前段保存中、镜头配置中、续录刚开始时点击停止；快速开始／切换／停止重复十轮。
4. Debug 一分钟分段录十分钟，跨自然分段切换镜头及保留10／30／60分钟；切换会额外产生短段，逐段检查声音、镜头方向、时长、间隔与保护状态。不要仅用“约十段”判断通过。模拟切换失败须回到原镜头续录，无法恢复则明确停录。
5. 默认字体与最大辅助字体检查：预览明显扩大、四个 Tab、停止按钮和保留菜单可达，无须滚动停止。检查详情展开／返回、素材保留反馈及值得回看导航。
6. 模拟低磁盘、真实温度变化、电话／麦克风中断及后台返回：警告始终可见，不能被保留成功提示覆盖，录像状态真实，后台停止后不自动恢复。
7. 完成原有2／4／8小时长期测试；本次未对连续录像稳定性作真机通过承诺。

## 双录按钮与兼容设备

以下均为 **NEEDS PHYSICAL DEVICE TEST**：

1. iPhone8 Plus待机及普通录像中点击“双录”：应显示“这台iPhone不支持前后同时录制”，列出XS／XS Max／XR及更新兼容机型的说明；不请求权限、不改变已有录像、计时或文件。详情页按钮也必须能弹出提示。
2. 在实际支持MultiCam且前后组合可用的手机，停止保存后选双录，再开始：上方后置、下方前置，预览与导出一致且均不镜像；用文字与声音验证方向、音轨和同步，检查最终720×1280、实际fps与H.264／AAC。仅支持标志不代表具体格式或负荷一定通过，失败必须明确提示并可切回单镜头。
3. 双录状态连续十分钟按Debug一分钟分段，检查每段画面、声音、时长、间隔；在自然分段、保存中保留10／30／60分钟并验证locked／pendingLock不被覆盖。
4. 首帧前快速停止、拒绝麦克风、电话／音频中断、后台、低磁盘、温度升高与合成停滞都应明确停止或失败，不得无限显示正在记录、空文件当成功或自动后台续录。
5. 双录中点击模式按钮提示先停止保存；保存后能切回单镜头并再次录制。单镜头录制中前后切换仍正常，重启默认单镜头，历史素材可见。
6. 小屏及最大辅助字体检查双录按钮、详情提示、计时、停止和保留入口；兼容设备独立完成2／4／8小时与AI／Web组合压力测试。
